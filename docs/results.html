Training a World Model on Synthetic Human Motion

Adapting LeWM's joint-embedding predictive architecture to learn dynamics from rendered human animations, using body pose deltas as actions and pretrained vision encoders.

March 2026 · Data: Prod_Renderings (200 episodes, 96k frames) · GPU: NVIDIA H200

Overview

We adapt LeWorldModel (LeWM) — a JEPA-based world model that trains end-to-end from pixels with SIGReg regularization — to learn dynamics of synthetic human motion renderings. The actions are frame-to-frame delta poses of the body root (3D translation + 3D axis-angle rotation), extracted from the poses_beta0_world and trans_beta0_world fields of the production rendering pipeline's NPZ data.

We compare three encoder configurations: a ViT-Tiny trained from scratch (the original LeWM approach), a frozen pretrained ViT-B/16, and an unfrozen (fine-tuned) ViT-B/16. The key metric is the copy ratio — whether the model predicts the next embedding better than simply copying the current frame.

Architecture

The pipeline follows the LeWM JEPA architecture: an encoder maps frames to embeddings, an action encoder maps delta poses to the same space, and an autoregressive predictor forecasts the next embedding conditioned on actions via AdaLN-zero.

Data Pipeline

Training data was fetched from the Prod_Renderings DynamoDB table, which indexes synthetic human motion renderings. For each rendering, we downloaded the compressed MP4 video from S3 (fast: ~200 episodes in 10 minutes) and the NPZ feature file containing SMPL beta-0 body poses.

The Copy Ratio Metric

A world model that merely copies the last observed frame would achieve zero prediction error in a static world. To measure whether the model actually learns dynamics, we compute the copy ratio: the model's prediction MSE divided by the MSE of simply repeating the last context frame. A ratio below 1.0 means the model predicts better than copying — it understands something about how the scene changes.

Why the absolute losses differ

The ViT-Tiny has much lower absolute prediction loss (0.0007 vs 0.0039), but its copy baseline is also far lower (0.00016 vs 0.0047). This means the tiny encoder produces embeddings where consecutive frames are nearly identical — it hasn't learned to distinguish visual changes. The pretrained ViT-B/16 produces embeddings that actually capture frame-to-frame differences, making prediction harder but more meaningful.

Implementation Notes

Embedder bottleneck fix

The original Embedder module had a hardcoded smoothed_dim=10, compressing the 30D concatenated action vector to 10D before the MLP. We fixed this to smoothed_dim=max(effective_act_dim, 10), preserving all action information.

Dual-path encoder

We extended jepa.py to support both HuggingFace ViT (pooling="cls", CLS token extraction) and timm/VJEPA encoders (pooling="mean", global average pooling over patch tokens). The encoder type is selected via config without code changes.

ClearML integration

All experiments log to ClearML via direct task.get_logger().report_scalar() calls (Lightning's self.log_dict is not auto-captured by ClearML without TensorBoard). Each metric gets its own plot with train/validate as separate series.

What's Next

The unfrozen ViT-B/16 comparison is currently training. Pending results, the next directions are:

  • True VJEPA checkpoint — the current ViT-B/16 is ImageNet-pretrained via timm, not VJEPA. A video-pretrained VJEPA encoder may produce even more temporally-aware embeddings.
  • More data — 200 episodes is small. The Prod_Renderings table has 26k+ renderings available.
  • VAE embedding correlation — comparing frame embeddings against precomputed VAE latents to measure whether the world model's representation aligns with animation structure.
  • Same-animation consistency — renderings sharing an animation_id (different camera/character) should ideally have similar frame embeddings.
  • Longer training — 30 epochs may not be enough for the unfrozen encoder to converge.
