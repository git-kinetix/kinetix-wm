01

What LeWM Learns

LeWorldModel is a Joint Embedding Predictive Architecture (JEPA) that learns a compact representation space from raw video frames. Unlike reconstruction-based methods that decode back to pixels, LeWM learns to predict future states in embedding space — producing representations that capture the physical structure of the environment without pixel-level supervision.

Key Insight

The representation is shaped by two forces: a prediction loss that makes embeddings predictively useful, and SIGReg that prevents collapse by enforcing the embedding distribution stays close to an isotropic Gaussian. This replaces the six loss terms used by prior end-to-end JEPAs with just two — reducing tunable hyperparameters from six to one.

The trained encoder maps each video frame to a 192-dimensional embedding vector. These embeddings have been shown to encode meaningful physical quantities (position, velocity, contact forces) and can detect physically implausible events through surprise estimation.

Representation Architecture

The training pipeline consists of five modules wired together. The encoder and projector form the representation backbone — these are what you keep after training. The predictor exists to provide the learning signal; it forces the encoder to produce embeddings from which future states can be inferred.

Vision Transformer Encoder

The encoder is a ViT-tiny from HuggingFace, trained from scratch (no pretrained weights). It processes each 224×224 frame independently, splitting it into 14×14 patches, and outputs a CLS token embedding that represents the full frame.

Python train.py:82–88 
encoder = spt.backbone.utils.vit_hf(
    cfg.encoder_scale,        # "tiny"
    patch_size=cfg.patch_size,  # 14
    image_size=cfg.img_size,   # 224
    pretrained=False,
    use_mask_token=False,
)

Projector

The projector is a 2-layer MLP with BatchNorm and GELU activation. It maps the ViT's hidden dimension down to the embedding dimension (192 by default). This bottleneck is what defines the representation space.

Python module.py:217–241 
class MLP(nn.Module):
    def __init__(self, input_dim, hidden_dim, output_dim=None,
                 norm_fn=nn.LayerNorm, act_fn=nn.GELU):
        self.net = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),   # hidden_size → 2048
            norm_fn(hidden_dim),               # BatchNorm1d(2048)
            act_fn(),                          # GELU
            nn.Linear(hidden_dim, output_dim),  # 2048 → 192
        )

Encoding Pipeline

The JEPA.encode() method in jepa.py chains the encoder and projector. Video frames are flattened along the batch × time axis for the ViT, then reshaped back. Only the CLS token from the last hidden state is kept.

Python jepa.py:29–45 
def encode(self, info):
    pixels = info['pixels'].float()
    b = pixels.size(0)

    pixels = rearrange(pixels, "b t ... -> (b t) ...")
    output = self.encoder(pixels, interpolate_pos_encoding=True)
    pixels_emb = output.last_hidden_state[:, 0]  # CLS token

    emb = self.projector(pixels_emb)
    info["emb"] = rearrange(emb, "(b t) d -> b t d", b=b)
    return info

ARPredictor (Training Signal Provider)

The autoregressive predictor is a 6-layer Transformer with AdaLN-zero conditioning on action embeddings. It takes a window of past embeddings and predicts the next one. While essential during training (it provides the gradient signal that shapes the representation), the predictor can be discarded if you only need the encoder for downstream tasks.

The predictor uses ConditionalBlock layers where action embeddings modulate attention and feed-forward outputs via learned shift, scale, and gate parameters — the same mechanism used in DiT (Diffusion Transformers).

Create the Python environment

LeWM requires Python 3.10. The project uses uv for fast dependency resolution.

Shell 
uv venv --python=3.10
source .venv/bin/activate
2

Install dependencies

The stable-worldmodel package bundles training utilities, data loading, and environment wrappers. The [train,env] extras pull in PyTorch Lightning, Hydra, WandB, and environment dependencies.

Shell 
uv pip install stable-worldmodel[train,env]
3

Verify GPU access

Training uses bf16 mixed precision, which requires an Ampere-generation GPU or newer (RTX 3000+, A100, H100).

Shell 
python -c "import torch; print(torch.cuda.get_device_name())"
Dependencies

The two core libraries are stable-worldmodel (environment, planning, evaluation) and stable-pretraining (training harness, data transforms, ViT backbone). Both are installed automatically via the pip command above.

Preprocessing Pipeline

Before training, the data passes through two automatic transforms defined in utils.py:

Image Preprocessing

Pixel frames are converted to tensors, normalized with ImageNet statistics (mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]), and resized to 224×224.

Column Normalization

Non-pixel columns (action, proprio, state) are z-score normalized: (x - mean) / std, computed over the full dataset with NaN values excluded.

06

The Two Losses

LeWM's stability comes from using exactly two loss terms with a single balancing coefficient. This is what makes training tractable on a single GPU without pretrained encoders or EMA targets.

L = Lpred + λ · LSIGReg     λ = 0.09

Loss 1: Prediction MSE

The prediction loss measures how well the predictor can forecast the next embedding from a context window of past embeddings and actions. This is what forces the encoder to produce predictively useful representations — if the embedding discards information needed to predict the future, this loss increases.

Python train.py:33–40 
ctx_emb = emb[:, :ctx_len]          # First 3 frames
ctx_act = act_emb[:, :ctx_len]      # Corresponding actions

tgt_emb = emb[:, n_preds:]          # Shifted by 1 step (ground truth)
pred_emb = self.model.predict(ctx_emb, ctx_act)

output["pred_loss"] = (pred_emb - tgt_emb).pow(2).mean()

With history_size=3 and num_preds=1, each training sample contains 4 frames. The first 3 frames (plus their actions) form the context; the 4th frame's embedding is the prediction target.

Loss 2: SIGReg (Sketch Isotropic Gaussian Regularizer)

SIGReg prevents representation collapse — the failure mode where all inputs map to the same embedding. It works by testing whether the empirical distribution of embeddings matches a standard Gaussian N(0, I) along many random projection directions.

How SIGReg Works

The characteristic function of a Gaussian is φ(t) = exp(-t²/2). SIGReg projects the embedding batch onto 1024 random unit vectors, computes the empirical characteristic function along each direction, and measures how far it deviates from the Gaussian reference. The error is integrated over t ∈ [0, 3] using a trapezoidal rule with Gaussian weighting.

Python module.py:10–36 
class SIGReg(torch.nn.Module):
    """Sketch Isotropic Gaussian Regularizer (single-GPU!)"""

    def __init__(self, knots=17, num_proj=1024):
        t = torch.linspace(0, 3, knots)
        window = torch.exp(-t.square() / 2.0)
        # Trapezoidal integration weights, Gaussian-windowed
        self.register_buffer("phi", window)
        self.register_buffer("weights", weights * window)

    def forward(self, proj):   # proj: (T, B, D)
        # 1. Random unit projection vectors
        A = torch.randn(proj.size(-1), self.num_proj)
        A = A.div_(A.norm(p=2, dim=0))

        # 2. Compute empirical vs. Gaussian characteristic function error
        x_t = (proj @ A).unsqueeze(-1) * self.t
        err = (x_t.cos().mean(-3) - self.phi).square() \
             + x_t.sin().mean(-3).square()

        # 3. Integrate with Gaussian-weighted trapezoidal rule
        statistic = (err @ self.weights) * proj.size(-2)
        return statistic.mean()

Why Only Two Losses?

Previous end-to-end JEPAs (like PLDM) require six loss terms: prediction, variance, covariance, attention entropy, capacity, and contrastive losses. Each introduces a hyperparameter. LeWM replaces all of these with the single SIGReg term, which implicitly enforces variance, isotropy, and non-collapse. The only hyperparameter is λ = 0.09.

Launching Training

Basic Launch

Training is a single command. Hydra resolves all configs and the data= override selects which dataset config to load.

Shell 
# Train on PushT (2D manipulation)
python train.py data=pusht

# Train on DMControl Reacher (3D control)
python train.py data=dmc

# Train on TwoRoom (2D navigation)
python train.py data=tworoom

# Train on OGBench Cube (3D manipulation)
python train.py data=ogb

Overriding Parameters

Any YAML parameter can be overridden at the command line via Hydra syntax:

Shell 
# Custom embedding dimension and learning rate
python train.py data=pusht wm.embed_dim=256 optimizer.lr=1e-4

# Larger batch size, fewer epochs
python train.py data=pusht loader.batch_size=256 trainer.max_epochs=50

# Disable WandB logging
python train.py data=pusht wandb.enabled=False

# Change the SIGReg weight
python train.py data=pusht loss.sigreg.weight=0.05

# Use a different random seed
python train.py data=pusht seed=42

What Happens During Training

Under the hood, each training step executes this sequence:

Learning Rate Schedule

The optimizer uses Linear Warmup + Cosine Annealing. Learning rate ramps up linearly during the first few epochs, then follows a cosine decay to near zero. This is handled automatically by the LinearWarmupCosineAnnealingLR scheduler from stable-pretraining.

08

Monitoring & Checkpoints

WandB Metrics

Three metrics are logged every training step. Here is what to watch:

MetricWhat It Tells YouHealthy Range
train/loss Combined training loss. Should decrease steadily. Task-dependent; decreasing trend is key.
train/pred_loss Prediction MSE. Measures embedding predictability. Should decrease. Plateaus indicate good representation.
train/sigreg_loss Gaussianity of embeddings. Lower = more Gaussian. Should stay small and stable. Spikes indicate collapse risk.
Collapse Detection

If pred_loss drops to near zero while sigreg_loss spikes, the representation is collapsing — all inputs are mapping to similar embeddings, making prediction trivially easy. Increase loss.sigreg.weight if you see this pattern.

Checkpoint Format

The ModelObjectCallBack saves two types of checkpoints to $STABLEWM_HOME/{run_id}/ after every epoch:

{name}_object.ckpt

Serialized Python object (the full JEPA module). Used by eval.py and swm.policy.AutoCostModel() for direct inference. Convenient but less portable.

{name}_weights.ckpt

State dict only (model.state_dict()). Load into your own model instance for downstream tasks. Better for reproducibility, portability, and fine-tuning.

Loading a Trained Encoder

After training, you can load the encoder for downstream use:

Python 
import torch
import stable_worldmodel as swm

# Option 1: Load the full model via stable-worldmodel API
model = swm.policy.AutoCostModel('pusht/lewm')

# Option 2: Load the pickled object directly
jepa = torch.load('path/to/lewm_epoch_100_object.ckpt')
encoder = jepa.encoder      # ViT backbone
projector = jepa.projector  # MLP head

# Extract embeddings from a frame
jepa.eval()
with torch.no_grad():
    info = jepa.encode({"pixels": frames})
    embeddings = info["emb"]  # (B, T, 192)

Advanced Tuning

Adjusting the Representation Dimension

The default embed_dim=192 produces compact representations. For tasks that require richer state information, increase this:

Shell
python train.py data=pusht wm.embed_dim=384

This affects the projector output, predictor input, and action encoder output dimensions simultaneously. Larger embeddings capture more detail but may be harder to regularize.

Tuning the SIGReg Weight

The λ parameter is the only loss hyperparameter to tune. The default 0.09 works well across tasks. Guidelines:

  • Too low (<0.01): risk of collapse. Prediction loss can cheat by shrinking the embedding space.
  • Too high (>0.5): embeddings become random-like. Prediction loss has no room to shape structure.
  • Sweet spot (0.05–0.15): both losses can coexist. The representation is informative and well-distributed.

Scaling the Encoder

The encoder_scale parameter accepts standard ViT sizes. Larger encoders may improve representation quality at the cost of training time and memory:

Shell
# ViT-small (~22M params)
python train.py data=pusht encoder_scale=small

# ViT-base (~86M params) - needs more GPU memory
python train.py data=pusht encoder_scale=base

Shell
python train.py data=my_task
HDF5 Format Requirements

Your HDF5 file must contain episodic data accessible via the stable-worldmodel HDF5Dataset class. Each episode should have a pixels dataset (uint8 images, shape (T, H, W, 3) or (T, 3, H, W)) and an action dataset (float32, shape (T, action_dim)). See the existing datasets for reference formatting.

Multi-GPU Training

PyTorch Lightning handles distributed training automatically. Set the number of devices:

Shell
# Use 4 GPUs with DDP
python train.py data=pusht trainer.devices=4 trainer.strategy=ddp
SIGReg & Multi-GPU

The current SIGReg implementation is marked as single-GPU only. In multi-GPU setups, the regularizer operates on the local batch, not the global batch. This may require increasing the batch size per GPU or using a synchronized variant.
